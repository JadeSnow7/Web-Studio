# 字体复用离屏诊断协议

真实 App 配对因 GUI 自动化就绪超时中断，不将控制组单窗与历史候选拼接。继续独立离屏诊断，结果不满足 W1 的 App/GUI 采用条件。

两份程序均来自既有 terminal-unicode-diagnostic.swift，控制/候选源唯一差异为已归档字体缓存补丁；swiftc -O、clang -O2、arm64、无 coverage。先各构建并执行一次校准（可能与轻量工具测试重叠，不用于收益汇总），随后固定六组交替进程顺序：C→E、E→C、C→E、E→C、C→E、E→C。每次原工具包含四个固定 fixture × 六轮，内部前后交替；正式统计先以每进程每 fixture 六轮 CPU 中位数聚合，再报告六对进程值与差值，不把 36 个内层样本伪装独立六对。

目标：验证字体获取减少能否在既有固定 100 次热提交 renderer 场景复现；保留冷提交和所有原始值。用户/系统 CPU 为进程 getrusage 秒；wall 含 GPU completion wait，不是 GPU 执行或呈现。无显示延迟与可靠内存峰值结论。每个进程保存输入 fixture 的字节数和 hash、字形/文本断言、全部记录与构建哈希。

正式测量期间不运行构建或其他压力测试。每对前后保存可获得的后台/热状态，主机已有 App 不清理。不会依据效果方向删除样本。若 Metal/fixture 失败则该批未判定，保留失败原因。
