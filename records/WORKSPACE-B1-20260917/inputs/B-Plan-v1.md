# Web Studio B 路线：项目工作空间方案

版本：B-Plan v1 · 2026-09-17

状态：用户已选择 B 路线；本文为待实施的产品与工程方案。细节采用下述推荐默认值，未修改现有产品行为。

## 1. 产品目标与首版范围

**把 Web Studio 做成一个能保存工作环境、切换项目、回来继续的原生工作台。** 用户围绕一项长期工作组织网页、终端、SSH 与 AI 问答。

首版应让用户完成这条完整路径：

> 创建“网站调试”工作空间 → 添加文档网页和项目终端 → 左右并排 → 提交所选资料给 AI → 切到另一项目 → 返回原布局和草稿 → 下次启动重新打开环境配置。

工作空间直接承接当前“分组”的组织位置。第一版不再叠加“项目—工作空间—任务组”三层结构。

| 首版 B1 必须具备 | 后续 B1.1 | 暂不包含 |
| --- | --- | --- |
| 工作空间创建、重命名、切换、关闭与归档 | 选择性保存问答和草稿 | 执行型 Agent、多 Agent 调度 |
| 本地保存入口、资源配置、布局、最后焦点 | 带明确历史范围的连续对话 | 工作空间账号/网络隔离 |
| 会话内切换保持运行时与各空间 AI 状态 | 可复用的启动组合 | 退出后后台守护 Shell/SSH |
| 重启恢复配置，终端手动启动、SSH 手动连接 | 配置导入导出 | 任意嵌套分屏、团队同步 |
| 清楚的地址路由、分屏对象、关闭后果 | 可选保存完整请求证据 | 自动执行启动命令 |
| 单次 AI 问答的来源选择、精确预览与发送闭环 | 根据使用证据增加跨空间资料引用 | 浏览器全功能补齐 |

B1 的“继续”分为两种：**同一次应用运行中继续原会话；重启应用后继续配置。** 页面表单、JS 状态、终端进程和 SSH 登录不能被纳入跨退出恢复承诺。

## 2. 统一对象与名称

| 对象 | 用户看到的名称 | 含义 |
| --- | --- | --- |
| Workspace | 工作空间 | 长期工作的组织与保存单位，目录可选 |
| Resource | 网页 / 终端 / SSH；管理场景统称资源 | 独立身份的内容与会话配置 |
| Pane | 视图 | 资源显示的位置；首版单视图或左右双视图 |
| Pinned destination | 常用入口 | 可重复打开的地址或目录配置，不是正在运行的会话 |
| Agent request | 问答 / 本次问题 | 一次问题与明确选择的快照 |
| Agent run | 请求状态，仅在详情出现 | 一次请求的执行记录，不当作用户任务 |

应用自有文案建议统一简体中文；系统菜单遵从系统语言，技术名称、地址与路径保留原文。界面不再混用 Tasks、Workspace、Tab 和 Resource 表达同一层级。

保留原生系统字体、语义颜色、磨砂背景、垂直资源导航；内容区不增加常驻标题栏，也不恢复水平标签栏。

## 3. 界面组织

```text
┌ 导航 ── [工作空间：网站调试 ▾] ── [地址 / 当前目标] ── 布局 ─ AI ┐
│ 工作空间                │                                  │ AI 问答 │
│ ● 网站调试       2 运行  │       文档网页     │    本地终端   │ 本次问题│
│   常用入口              │                    │               │         │
│     项目文档            │                    │               │ 来源 2  │
│   打开的资源            │                    │               │ 读取时间│
│     文档         [左]   │                    │               │ 预览    │
│     开发服务     [右]   │                    │               │         │
│   + 网页  + 终端  ···   │                    │               │ 问题输入│
│ ○ 接口排查       1 运行 │                    │               │ 发送    │
│ + 新建工作空间          │                    │               │         │
└───────────────────────┴────────────────────┴───────────────┴─────────┘
```

这是结构示意，非最终像素稿。“运行”数字必须来自真实会话状态；不把已配置或待启动资源算成正在运行。

- **左侧**显示工作空间列表，只展开当前空间的常用入口和资源。组名前的折叠按钮只控制展开，不切换内容；名称按钮才切换工作空间。
- **顶部空间切换器**是隐藏侧栏后的完整导航入口，也能找到在其他窗口打开的空间。它替换现有容易与侧栏重复的资源胶囊角色；资源快速切换交给侧栏和 ⌘K。
- **中部**继续让网页与终端平等占据内容区。侧栏标记“左 / 右”，当前焦点仍用边缘与选择态表达。
- **右侧**是当前工作空间的 AI 问答。隐藏面板不删除问题或终止请求；工具栏显示实际请求状态和返回入口。
- **空空间**提供“打开网页”“新建终端”“连接 SSH”，不因选择空空间而自动制造空白资源。⌘T 仍显式创建空白网页。
- **工作空间设置**集中名称、关联目录、保存状态、共享网站登录说明和归档入口，避免把这些内容塞进地址栏。

## 4. 关键交互规则

### 4.1 创建与进入

创建时只要求名称，目录为可选项。关联目录后，新建本地终端默认使用该目录；没有关联目录时使用用户主目录。指定目录动作使用原生目录选择器。目录不可访问或已移动时保留原配置并要求重新选择，不静默换到其他目录。

首次启动进入“临时空间”。临时空间在应用会话内保留，但不跨退出保存；顶部明确“临时空间 · 未保存”，提供“保存为工作空间”。用户为它命名后才进入持久化范围。B1 的其他新建空间默认自动保存。

临时空间不用于承诺隐私隔离：网站仍使用现有共享 WebKit 数据存储。

### 4.2 工作空间切换

切换到本窗口承载的另一空间时，恢复该空间的资源选择、左右布局、分隔比例、侧栏/AI 展开偏好及 AI 草稿。先撤销未提交的地址编辑、关闭临时命令面板，再将焦点交给目标空间最后使用的有效位置。表单有未保存输入时先留存草稿或要求处理，不能直接丢弃。

原空间的网页和终端继续保留在本次应用会话中；AI 请求继续，并把结果写回原空间。切换空间不会自动读取新资源或改变已经发送的请求。

| 目标空间状态 | 点击后行为 |
| --- | --- |
| 本窗口中已载入 | 直接恢复该空间展示 |
| 其他窗口中已载入 | 激活那个窗口并选中该空间；不创建第二份运行时 |
| 已保存但未载入 | 当前窗口载入配置，按恢复规则展示 |
| 已归档 | 在归档列表选择“恢复”，再打开 |
| 文件损坏或版本不支持 | 展示恢复说明；不覆盖原文件，也不伪装成空空间 |

首版同一空间最多归属于一个窗口。同一个窗口可以承载多个空间，但一次只显示其中一个。暂不做运行中空间的跨窗口拖移；可以在新窗口打开尚未载入的空间。

### 4.3 资源创建、查找与移动

- 每个空间保留“新网页”“新终端”快捷按钮，··· 菜单提供 SSH、指定目录终端和空间管理。
- ⌘L 操作当前焦点资源，输入时显示即将执行的结果：网页导航、新网页、新终端或新 SSH。终端上输入网址创建同空间网页；输入终端路径不会改变已有进程的工作目录。
- ⌘K 分为“资源”和“操作”，默认本空间优先，并提供所有空间查找。同名条目显示空间名、类型和地址/目录摘要。
- 搜索到未启动终端只定位到“待启动”资源，不顺便启动 Shell；SSH 同理。
- 原始跨组“移动资源”在 B1 中收敛为“复制入口到其他空间”。它只复制目的地配置，不搬动正在运行的终端、网页会话或历史快照；文案不继续叫“移动”。跨空间转移运行时留待独立生命周期方案。

上述范围调整减少跨空间会话迁移风险，也确保 AI 快照始终能指向原资源。复制与移动语义不同，需要同步菜单、命令及说明。

### 4.4 分屏与焦点

“与另一资源并排”打开本空间资源选择器，可选已有资源、新网页或新终端。已显示在另一侧的资源只切换焦点，不重复挂载。

单击未显示资源替换当前焦点视图；另一侧保持原状。菜单提供“在左侧显示 / 在右侧显示”，与拖放表达相同结果。地址栏控制当前焦点侧；面板动作则使用打开时捕获的空间、资源与视图。

切换空间保存各自布局。首次分屏可出现一次简短说明：“点击内容区切换操作对象；收起视图不会结束终端。”不长期覆盖内容。

### 4.5 关闭、结束与归档

| 操作 | 行为 | 保留的内容 |
| --- | --- | --- |
| 收起当前分屏 | 只解除视图引用 | 资源及运行会话都保留 |
| 关闭网页（× / ⌘W） | 释放网页运行时，移出打开资源列表并保存变更 | 对应常用入口保留 |
| 关闭终端资源（× / ⌘W） | 有运行会话时确认，再结束并移出列表 | 对应常用入口保留；不承诺恢复进程 |
| 结束会话（终端菜单） | 结束进程，保留资源行与目的地 | 行显示已结束，可明确再次启动 |
| 关闭工作空间 | 保存配置，处理运行请求/会话，卸载该空间 | 已保存空间仍在列表，能重新打开 |
| 归档工作空间 | 先按关闭流程卸载，再移到归档列表 | 配置可恢复；常用列表中隐藏 |
| 关闭窗口 | 处理本窗口承载的全部空间，包括未显示空间 | 已保存配置保留 |
| 退出应用 | 处理全部窗口的资源与保存状态 | 已保存配置保留；所有原会话结束 |

终止确认写清空间名、终端数量、AI 请求数量与后果，默认可取消。正常切换、收起分屏、可恢复的重命名不弹确认。

保存失败时，“关闭/退出”不能静默丢掉最新配置：提供“重试保存”“取消关闭”，以及明确标识后果的“不保存并关闭”。终止已经开始后不能假装取消能够复活已结束进程；界面区分准备关闭与正在关闭，失败保留可重试状态。

B1 只提供可恢复归档，不做永久删除空间。临时空间关闭前，如有值得保留的配置或 AI 内容，提供保存空间或明确丢弃的选择；保存空间本身不自动把 AI 正文写入磁盘。

### 4.6 AI 问答随空间归属

每个工作空间拥有独立的草稿、已选来源、预览与问答记录。B1 中它们仅在本次应用会话保存；界面常显“问答仅保留至关闭空间或退出应用”。“隐藏面板”和“关闭空间”后果不同。

准备流程合并为一处：

```text
输入问题 → 添加当前空间来源 → 读取 → 审阅精确快照 → 发送
                            ↘ 失败：重读 / 明确移除失败项
```

来源标签常显在输入框旁，标注待读取、采集时间、截断与读取失败。只打开资源选择器不会读取或发送正文；没有可靠内容变更信号时只显示采集时间，不伪造“已过期”判断。

每次仍发送“当前问题 + 本次快照”，不自动加入历史。原“新建对话”改为“新问题”：保存当前会话内的问题记录与未发送草稿，新建独立问题；用户可返回之前的问题。多个问题可以编辑，首版每个工作空间同一时刻只发一个请求，避免把并行执行引入本次范围。

“用原快照重试”不重新读取页面；“更新资料后重新提问”创建新请求。取消、空间关闭、资源重启的迟到回调均不能写入新请求。资源重启后生成新的运行实例标识，历史快照仍保留采集时的实例信息。

B1.1 才增加“在此设备保存问答”的显式设置，并定义删除、保留期限与证据范围。保存回答但没有保存原快照时，历史条目标明“原始上下文未保留，不能原样重试”。长期保存与连续对话是两项独立能力。

### 4.7 窄窗口与键盘

内容区域优先获得空间；当导航、双视图与 AI 无法同时可用时，提供“内容 / AI”显式切换，保留原布局和草稿，不用持续压缩三栏来维持形式完整。侧栏收起后，顶部空间切换器和 ⌘K 仍可访问全部对象。

保留 ⌘T、⌘⇧T、⌘L、⌘K、⌘W 与已有布局快捷键；不抢占网页、终端或输入法正在使用的组合键。具体宽度阈值通过 900×560、常用笔记本窗口与大窗口原型验证，暂不把任意断点写成硬性规格。

## 5. 保存与恢复契约

| 数据 | B1 保存方式 | 重启后行为 |
| --- | --- | --- |
| 空间 ID、名称、可选目录、归档状态 | 本地持久化 | 恢复空间目录 |
| 资源 ID、类型、目的地、自定义名称、顺序 | 本地持久化 | 恢复描述；不因此启动终端 |
| 常用入口 | 本地持久化，与运行资源分开 | 可再次打开独立资源 |
| 左右视图引用、比例、最后焦点、面板偏好 | 本地持久化 | 校验引用后恢复布局 |
| 网站 Cookie / 登录 | 沿用现有 WebKit 存储 | 仍共享，不保证网站无需重新登录 |
| 网页内存、未提交表单、页面 JS、完整返回历史 | 不保存 | 网页重新加载，不伪装原页面仍存活 |
| 终端输出、Shell/SSH 进程状态 | 不保存为可恢复会话 | 显示“待启动 / 待连接” |
| AI 草稿、问答正文、预览与请求快照 | B1 内存保存 | 关闭空间/退出后不恢复，UI 明示 |
| Provider 配置与密钥 | 延续现有配置及 Keychain 规则 | 不复制到工作空间文件 |

自动保存覆盖资源创建/关闭、常用入口编辑、名称与目录、布局、网页提交后的目的地等配置变化；输入中的地址草稿不当作已提交目的地保存。

建议连续拖动分隔线时采用约 500ms 合并写入，停止拖动及显式关闭时刷新待保存内容。500ms 是初始实现参数，后续用写入次数、主线程负担及故障恢复校准。界面只有保存成功后才能显示“已保存”；失败显示持久的“尚未保存”及重试入口。

启动时先加载空间目录，只载入上次活动空间的配置；其他空间按需载入。可见网页按需加载，隐藏网页延后创建运行时；终端与 SSH 必须由用户点击启动/连接。不可用目录、无效地址、损坏布局按项报告，其他有效资源仍可使用。

## 6. 架构与内部契约

当前 `StudioWindowRoot` 每窗口创建一个 `StudioModel`，后者同时持有资源、分组、窗口布局与 Agent。需要将“窗口展示”和“空间状态”拆开，但继续复用真实 WebKit 与终端运行时。[当前装配](</Users/huaodong/workspace/Web Studio/Web Studio/ContentView.swift:220>)

当前 `registerLocalTerminal` / `registerSSH` 会创建并启动会话，**恢复配置必须使用独立的描述加载路径**，不能把反序列化接到现有新建入口上。[当前资源创建](</Users/huaodong/workspace/Web Studio/Web Studio/ResourceModel.swift:172>)

以下名称是拟新增边界，尚未存在于产品中：

```text
应用装配
 ├─ WorkspaceRegistry：空间目录 + 唯一窗口归属
 ├─ WorkspaceRepository：版本化配置读写
 └─ WindowCoordinator：当前窗口的空间切换与关闭编排
      └─ WorkspaceSession（每个载入空间一份）
           ├─ ResourceStore：资源与真实运行时
           ├─ WorkspaceLayout：布局、最后焦点
           └─ WorkspaceQuestions：草稿、预览、请求与问题记录

PanelCoordinator：仍属窗口，捕获 workspaceID / resourceID / paneID
```

Registry 的引用不能让已经关闭窗口的会话继续偷偷存活。关闭窗口必须枚举它承载的所有 WorkspaceSession，包括非活动空间，等待清理后释放窗口归属。全局退出只汇总一次确认，再执行已有会话清理，不对每个空间重复弹窗。

| 内部操作（拟定） | 输入与输出 | 关键契约 |
| --- | --- | --- |
| openWorkspace | 空间 ID、窗口 ID → 激活本窗或定位他窗 | 同一空间无重复宿主；读取失败保留原窗口状态 |
| restoreDescriptors | 版本化配置 → 描述与校验问题 | 不启动进程、不请求 AI、不执行命令 |
| startResource | 空间/资源 ID → 新运行实例或明确错误 | 同一资源连续点击不重复启动；待结束时拒绝新启动 |
| saveWorkspace | 配置、期望修订号 → 新修订或失败 | 旧异步写入不能覆盖新版本 |
| captureContext | 问题 ID、来源 ID 集合 → 有版本的预览 | 选择变化使旧预览失配；读取错误明确 |
| submitQuestion | 问题、冻结快照、Provider 配置 → 请求 ID | 目标空间不随前台切换；请求不可变 |
| closeWorkspace | 空间 ID、已处理关闭意图 → 完成/仍在关闭/失败 | 等待已有关闭任务；重复调用不重复释放 |

这些是行为合同，不预先承诺具体 Swift 签名。实施时以领域类型与协议为字段权威，UX-CONTRACT 引用可观察行为，避免再维护一份手写字段副本。

### 配置格式与故障处理

建议 B1 每个工作空间一份版本化 JSON，由单个持久化组件串行写入；不使用 UserDefaults 保存整套资源状态。文件放在应用的 Application Support 范围；本方案没有实际创建用户配置。

最小字段包含 schemaVersion、workspaceID、revision、名称、关联目录、资源描述列表、入口列表、布局与最后焦点。运行状态、输出、快照、Keychain 内容均不进入该格式。

空间目录从各空间文件元信息派生，索引可重建，不依赖“索引和空间文件必须同时写成功”才找得回数据。写入采用临时文件、完整校验、替换和上一份有效备份；承诺范围由故障注入结果决定，不能仅因使用原子替换就宣称断电不丢数据。

- 未知新 schema：只读保护，不降级覆盖。
- 主文件损坏：保留原件，尝试有效备份；无备份时隔离该空间并显示恢复入口。
- 布局引用丢失资源：保留有效资源，修复到可显示布局并提示，不默默重建终端。
- 写入失败：保留内存改动与错误状态；不标记已保存，不阻止无关空间工作。
- 重复 ID / 不支持的目的地：拒绝冲突项并报告，不执行任何内容。
- 同一资源的并发启动、关闭及迟到回调：由空间/资源/实例身份与请求代次核对，避免污染新实例。

### 迁移与回退

当前分组与资源没有磁盘持久化源，应用升级并重启后不能凭空导入旧进程内状态。首版不得声称“自动恢复此前所有分组”。如果需要保留升级前的活动环境，应先单独提供配置导出桥接版本，再升级；这不是 B1 的已存在前提。

新版本内部把旧 groupID 的组织用途迁移到 workspaceID，模型测试用现有分组样本验证名称、资源归属与布局转换。对已运行会话的对象迁移必须独立验证，不能为迁移新建第二个终端。

发布前保留已有配置备份；回退到旧应用时保留新配置文件，旧应用不认识工作空间数据就不读取。后续重升可再次载入；不承诺旧版本拥有新功能。B1 后的 schema 迁移都需版本化、备份与失败路径测试。

## 8. B1 验收场景

| 场景 | 输入与操作 | 必须出现的结果 |
| --- | --- | --- |
| 空间隔离 | A/B 各建网页、终端、AI 草稿并来回切换 | 各自资源、布局与草稿正确；请求结果归原空间 |
| 运行时保持 | A 运行可观测测试进程，切 B 再返回 | 原会话身份保持，无额外启动；输出仍属于 A |

| 隐藏空间关闭 | 窗口显示 B，但 A 仍有运行终端 | 关闭提示包含 A；确认后等待 A/B 完整清理 |
| 配置恢复 | 保存双视图及网页/终端/SSH描述，退出重启 | 配置与布局恢复；终端和 SSH 待启动，无 AI 自动请求 |
| 保存故障 | 注入写入失败、截断 JSON、未知 schema | 显示未保存/恢复说明，原件保留，不覆盖为默认空配置 |
| 目标稳定 | 打开面板后切换/关闭目标资源 | 取消临时流程或显示原目标失效，不重定向到新资源 |
| 分屏关闭 | 收起终端视图后重新打开；再明确关闭资源 | 前者进程存活，后者确认并终止；只释放一次 |
| 快照与重试 | 采集后变更页面、关闭来源或重启终端 | 原请求来源不变；重读后产生新请求，实例归属可区分 |
| 新问题 | 草稿/旧答案存在时创建新问题 | 会话内旧问题可找回；不清空整段记录 |
| 窄窗与辅助输入 | 900×560、长中英文标题、IME、键盘、VoiceOver | 关键入口可达；无误提交/串焦点；状态可读 |
| 临时空间 | 临时空间添加资源后尝试关闭 | 明确保存配置或丢弃；不声称长期保存问答正文 |

采用进程/运行时身份、启动计数、Provider 调用计数、磁盘回读和真实界面行为作为证据。模拟器可验证错误路径，但真实 Shell/SSH/模型链路单独验收；模型测试不能证明焦点与输入法正确。后台资源保持测试与现有性能基线分开，不凭这一轮场景检查宣称性能改善。
