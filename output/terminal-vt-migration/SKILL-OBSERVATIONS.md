# 本次流程观察（仅记录，未修改 skill）

- CI 根因必须绑定 head SHA、run/job 与失败步骤；后续 skipped 编译步骤不能证明语法失败。用户给出的 `def now() -> str:` 本身是合法 Python 定义。
- 证据分为可迁移导航与原始封存内容；链接修复不应无差别改写封存结果，也不应一律删除 records。
- 子代理交付“测试通过”仍需主线程用反例审查指标语义。本次工具的字面量 ESC、CPU 分母、负计数钳制、异常错误分类和单点样本状态均经审查修正。
- 应在采样前记录可比条件：真实窗口可见性、构建配置、网格、字体、显示缩放、warmup、负载与重复次数；默认网格不同须保留限制。
- 文档应分开描述接口契约、脚本回归、真实 GUI、人工 IME、性能和远程 CI；任何一类通过不替代其余类别。
- 原始记录和 CI 推送后的状态回执应分别标记；不要把“已推送实现”描述为本地所有回执也已提交。
- 采样对象须核对完整 executable，而非假设 shell 父 PID 就是 App；旧后端含 login 中间进程，主线程首轮误采已隔离为 rejected，随后用 App PID 重采。
- 主线程执行记录也必须传 --repo/--state：本轮构建/smoke虽保存源码哈希和真实退出结果，但缺少task revision token，结构校验提示不可作为当前最终门禁证据；已标stale保留。正式最终门禁须按绑定版本重跑，不能补填token伪装执行时已绑定。

- 外部 AX 几何也可能含无穷坐标（例如隐藏工具栏节点），真实进程复验暴露了只测无窗口自身 PID 的盲区；必须保留无效值错误并用真实目标复验。
- revision 排除仅覆盖固定记录文件名；STATUS/ACCEPTANCE/M2-CURRENT-RESULTS/MANUAL-ACCEPTANCE 等仍影响 token。先冻结规范文档，再将运行回执写入 evidence 与 task-state/work-log，防止为写结果使刚完成的检查 stale。
