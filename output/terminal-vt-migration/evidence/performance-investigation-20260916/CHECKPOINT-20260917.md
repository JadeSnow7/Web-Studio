### 完成边界与内存限制

输出 write+DSR 往返中位数（VT / 旧，毫秒）：ASCII 3.405 / 6.052；中文 2.630 / 4.943；混合 4.077 / 8.032。每轮负载实际写出字节、文件 hash、回执和末屏均核验。DSR 只支持“写出加查询回执往返”边界，不能当作画面已呈现、输入到显示延迟或终端净处理吞吐。内部解析结束没有独立时间标记；未据此宣称吞吐提升。

RSS 是离散进程观测和末次值；采样最大值不是可靠峰值，也不是稳定持有量。分配总量、持有对象归因和可靠峰值尚未完成独立 profiler 轮次。App、PTY 子进程不能合并报告：现有 ps 子进程快照不足以构成场景累计 CPU；新并发 fixture 已实现自身 CPU 差值，但真实 App 场景尚未运行。

GPU 利用率、帧时间、实际 presentation 和输入显示延迟均未获可靠关联，不报告数值。旧 trace 的零目标事件不表示零 GPU 消耗；未对嵌套 GPU 区间求和。

## 构建与实际工作量差异

原人工 GUI PID 21524、冻结构建、无 coverage Release、规范化比较副本、字体实验、历史容量副本分别留有来源和二进制 hash。HEAD ced7edc 不是实际构建来源的替代。旧冻结 legacy 含 coverage，而原 VT 不含；本轮 clean 两端均重新采用 Release、arm64、coverage 关闭并核查符号。原三轮 0.15 / 0.07 秒不得与新协议相减宣称收益。

**新发现：默认历史容量不同。** 同一 10,000 行 mixed 输出后，默认 VT 实际最早可见行为 9558，旧为 4537。固定依赖源码中 VT Terminal 默认 max_scrollback_bytes=10,000，而旧配置 scrollback-limit=10,000,000；页分配粒度还会影响实际保留量。因此上表输出/空闲只能作为各自默认历史策略的整体后端比较，不能称等量历史的内存/滚动比较。fallback、连字和中间帧实际绘制量仍未完全等价。

在单独 worktree 设置 VT 64MiB/10,000 行上限、旧副本 64MiB；不与字体实验叠加。两端 GUI 已确认 0–9999 行，见 history-pilot-vt-01、history-pilot-legacy-01 和 history-copy-manifest.json。此项是测量条件对齐，不是生产优化。C 接口设置检查错误并释放失败对象；patch 与绑定 Release 构建在 experiments/history-limit-normalization.patch、history-normalized-build.json。

交互试采 history-interactive-pilot-01 的四轮身份、DSR、动作与采样关联均有效。实际路径为 9956→0→9956（viewport 首行总位移 19,912 行），不意味着中间每行都绘制。resize 宽度 1400↔1176pt、网格 134↔108 列、45 行，高度 859pt，末屏 9956–9999 一致。正式批次加入 2.5 秒发起节奏并记录实际偏差；AX、截图及查询开销在动作包络内，不能当净滚动或帧性能。

第一正式批次因界面重连启动额外隔离实例，身份校验拦截，未跳过校验；第二完整重跑在第一组末尾再次锁屏。所有失败和有效片段保留，分别见 history-interactive-matrix-01、-02；不混池补足六对。matrix-02/interruption.json 记录只 SIGINT 自有协调器，触发 finally 清理，不关闭用户原 GUI。

## 热点、推断与假设

**事实：** 主线程在两个最小环境 App 中各进行独立 5 秒 / 256MiB 上限 sample 采集，并放大为 500×10,000 行 mixed（255,000,000 字节）。每组 505 个结果含预热/重置且 DSR 全部匹配；有效 call tree 数值行分别 3696、2087，全部解析，未触及上限。实际收尾墙钟 6.206、6.645 秒；采样仍固定 5 秒。先前 8 秒外层收尾上限导致失败的 profile-control-02 保留，不能重新标为通过。原始采样在受限临时目录处理，只有过滤、脱敏后的调用树归档；未打印环境或原始 trace 元数据。

**事实：** 控制组 TerminalMetalRenderer.swift:358 的字体调用分支有 2080 个包含子调用的采样；其 __NSGetSystemFontVariants 子分支最大 1803。实验组该字体函数的最大单分支为 4，仍可见 frame 内字典查找。这是采样分支权重，不能按毫秒精确换算，也不能与嵌套子项相加成为利用率。实际中间绘制帧数未插桩，故不宣称等帧的 CPU 归因。

**有证据支持的推断：** 两个 cell 循环（renderer 249、358 行）每次调用 font(for:)，后者按 bold/italic 取系统字体；帧内至多四种 traits 的复用可减少重复 AppKit/CoreText 字体描述符查找。源码、调用栈变化和无 profiler CPU 对照方向一致，足以支持该最小实验。

**尚待验证：** 这不是 Unicode 专属根因证明。纯 ASCII 同样走字体获取，新增字形、重复字形、同字节量和同可见 cell 数诊断矩阵尚未完成。PTY read→Data 拷贝（TerminalPTYTransport.swift:280）、C 解析与状态更新、快照 C/Swift 分配（TerminalVTCore.swift:159、StudioVTCore.c:122）、atlas 缺键整批重建、CoreText fallback/shaping、纹理上传和 Metal 提交均有代码路径，但没有足够阶段计数把剩余成本拆清。未采到某锁等待或 raster 栈不表示不存在其消耗。

TerminalVTBackend.swift:175–179 在 visible 判断之前生成 snapshot，支持“隐藏且持续输出仍可能做快照”的代码推断；隐藏空闲低 CPU 无法验证此假设。未修改此路径。

## 排序后的候选与实验结果

| 排序 | 候选及观察依据 | 机制、收益场景 | 风险、验证与决定 |
|---|---|---|---|
| 1 | 帧内四 traits 字体复用；真实字体调用栈热点 | renderer.render 内局部字典，两循环共用；可能影响所有有文字重绘 | 低成本、每帧有界，不改跨帧失效、fallback、atlas或在途资源。仅隔离实验；回退为丢弃单文件 patch。暂不采用生产，待完整场景/GUI回归 |
| 2 | 隐藏输出快照节流；仅代码线索 | 在保持解析/状态推进下避免不消费的快照 | 恢复可见、选区、AX状态可能过期；先测隐藏持续输出与恢复内容。证据不足，未实验 |
| 3 | atlas 增量/分代复用；缺键全重建路径 | 新增字形时减少重复raster/上传 | GPU在途纹理生命周期、容量/淘汰、内存增长风险较高；需新增字形计数与可靠栈。暂不实验 |
| 4 | 快照/脏区分配减少 | 减少跨C/Swift对象与全cell遍历 | 正确性边界广，需分配/dirty计数；暂无足够热点证据，不改 |

仅候选 1 实验。完整六对 CPU 秒（control → cache）：0.041875→0.078593、0.036906→0.031392、0.031370→0.013688、0.026600→0.018131、0.027217→0.016135、0.030596→0.016609。中位数 0.030983→0.017370（约下降44%），首对反向保留；不是每次都更快，也不是延迟下降44%。write+DSR 中位数 4.472→4.398ms，变化很小。见 experiments/font-mixed-results-v2.json、font-mixed-matrix-02 和绑定执行记录。

独立 Release 构建、Metal smoke，以及控制/实验各自绑定的离屏对照通过。九幅 BGRA 完全一致，覆盖四 traits、宽字符/组合字符/Emoji、历史和 resize、多个提交；见 experiments/font-pixel-comparison-v2.json。离屏一致不替代 GUI 隐藏恢复、实际呈现或资源压力回归。主仓库只有新增检查工具，生产 renderer 保持原样。

先审固定源码和依赖，再查官方资料：Apple [NSFont](https://developer.apple.com/documentation/AppKit/NSFont) 提供按尺寸/weight获取系统等宽字体的接口；[call tree 文档](https://developer.apple.com/documentation/xcode/analyzing-cpu-profiles-with-call-tree-views)解释不同采集器的权重来源。这些文档不承诺缓存调用成本；收益判断来自本机证据。
