# Web Studio M2 性能调查结果（2026-09-17）

本轮完成八类基础场景共96个正式 App 测量窗、四负载24轮VT离屏诊断、独立调用栈和存活分配快照；一个有调用栈依据的帧内字体复用实验留在隔离构建。**没有修改生产渲染实现或默认后端，没有提交推送、M3、移除依赖、合并或部署。** 本报告交付性能调查结果与明确限制，不代表M2完整验收或发布条件成立。

## 2. 构建、负载和观测限制

HEAD保持ced7edc。原人工GUI PID21524、五个冻结二进制、clean无coverage Release、字体/格距比较副本、历史容量副本和字体实验各有独立来源与hash。旧冻结legacy带coverage而VT没有，因此原三轮0.15/0.07秒不再作为同配置定量比较依据，也没有据此改渲染。当前clean对照均Release arm64、coverage关闭；本次最终核对原GUI两文件与冻结五文件均匹配，见[收尾核验](final-investigation-cleanup-20260917.json)。HEAD不是实际构建来源的替代。

默认10000行mixed后VT最早可见9558、旧4537；固定依赖VT默认max_scrollback_bytes=10000、旧scrollback-limit=10000000，页分配粒度亦影响保留行数。独立副本VT配置64MiB/10000行、旧64MiB后均可见0–9999。见history-copy-manifest.json、experiments/history-limit-normalization.patch和绑定构建。容量对齐是测量准备，不是生产优化。

后台原有Apps保持运行；每轮before/after CPU、内存压力和可获得热警告留证。ps百分比是平滑读数，RSS求和可能重复共享页；无热警告不等于恒温。锁屏、错误PID、输入方未准备、现场函数绑定失败及UI服务中断均保留，未按CPU结果筛选补测。历史交互第一组中断后按EVENT-029预先声明续跑第2–6组；原整体失败不改写。正式并发先经独立试采03通过再开始六组。所有profiler/内存场景排除无profiler基线。

RSS只有离散和末次值，采样最大值不叫可靠峰值。独立单次heap/VM旁证：VT160689个存活分配节点、22.817MiB heap、119.300MiB footprint；旧167273节点、26.488MiB heap、157.800MiB footprint。采样时点/驻留时长不同，不能据此排序内存优劣；节点字节与footprint不可相加。累计分配量、稳定持有对象、生命周期/泄漏归因仍未测得。详见[内存说明](MEMORY-SNAPSHOT-RESULTS-20260917.md)。

## 3. 热点与Unicode归因

**已测事实：** mixed放大负载的控制/字体实验各有一次有效5秒调用栈，数值行3696/2087全部解析；控制renderer:358字体分支权重2080，子分支__NSGetSystemFontVariants最大1803，实验对应函数最大单分支4。额外持续ASCII并发5秒栈数值行3349/2651全部解析，VT renderer:358字体分支487、子分支425，snapshot分支15；AX入口两端分别出现71/79。采集最小环境、原始数据私有临时目录处理，只归档过滤脱敏调用树，未打印环境或raw trace metadata，未触及上限。

这些是包含子调用的采样分支权重，不是精确毫秒，也不能把嵌套项求和。线程等待栈不是CPU忙碌。主线程运行/等待可见，但没有完整调度区间与锁竞争持续时间，未将零匹配当作零消耗。

**支持的推断：** renderer两个cell循环249/358反复调用font(for:)，457附近按traits获取系统等宽字体；帧内至多四traits复用能减少重复AppKit/CoreText字体描述符工作。调用栈变化与无profiler实验CPU方向一致，是本轮最有依据的候选。持续ASCII也出现该路径，因此这是通用文字重绘成本，不能称Unicode专属根因。

**Unicode诊断事实：** VT-only离屏4负载×6轮，实际字节/cell/head/cluster与文本逐行核验，所有glyph ID非0。ASCII120与CJK60同5280占用cells，100次热提交CPU中位1.928825/1.562835秒，CJK并未更慢；但非空head数不同。ASCII120与CJK40同5368bytes，head/cell不同；不能单独归因于编码。重复/40种CJK同bytes/cells/head，热100次1.374676/1.396290秒，约1.6%差；首帧atlas冷中位18.446/19.688ms但不同字形首两轮显著更高，全部保留。fresh renderer不等于系统字体缓存冷。

同renderer逐cluster CoreText检查表明ASCII使用.AppleSystemUIFontMonospaced-Regular，CJK使用.PingFangUITextSC-Regular，ligature=0；不证明旧后端相等。[诊断详细结果与限制](UNICODE-DIAGNOSTIC-RESULTS.md)、[全部24轮](unicode-diagnostic-results.json)。wall包含command等待，不是GPU执行或presentation时间；固定100提交与App合并刷新不同。

**尚待验证：** PTY读取/Data复制、C解析与状态更新、C/Swift快照分配、脏区与atlas全量重建、纹理上传、Metal在途资源和隐藏输出快照仍有代码路径，但不足以分摊剩余CPU。隐藏空闲低CPU不能验证持续隐藏输出；backend在可见判断前snapshot只支持代码假设。当前不把任何一项预设为全部根因。

## 4. 候选排序与唯一隔离实验

|排序|依据与机制|影响/风险/最小验证与决定|
|---|---|---|
|1 帧内traits字体复用|真实栈+单因素CPU改善；render局部字典复用至多四traits|文字重绘场景；每帧有界，保持fallback/跨帧失效/atlas和在途纹理语义。低成本、回退单文件patch；仅隔离，未采用生产|
|2 atlas缺字重建调查|源码缺key时整批重建，字形多样性首帧波动有旁证|新字形/冷态可能获益，尚无稳定atlas归因；先计数实际新glyph/raster/上传。纹理在途、容量淘汰及维护风险高，未实验|
|3 隐藏输出快照节流|snapshot在visible判断前，只有代码线索|先测持续隐藏输出与恢复内容/AX；过期状态风险，证据不足，未实验|
|4 快照/脏区/PTY复制减少|现有分配与全cell遍历路径，缺可信阶段占比|正确性边界广，需分配生命周期/dirty计数；不为产生diff而改写|

先审仓库与固定依赖，再查[Apple NSFont](https://developer.apple.com/documentation/AppKit/NSFont)及[call tree官方文档](https://developer.apple.com/documentation/xcode/analyzing-cpu-profiles-with-call-tree-views)。文档不承诺缓存调用成本，收益来自本机证据。

字体实验六对CPU秒（control→cache）：0.041875→0.078593、0.036906→0.031392、0.031370→0.013688、0.026600→0.018131、0.027217→0.016135、0.030596→0.016609。中位0.030983→0.017370（约下降44%），首对反向保留；不是延迟下降44%。write+DSR中位4.472→4.398ms，变化很小。只改isolated renderer帧内字体获取一个主要因素，同Release/协议；未合入生产。

独立Release、Metal smoke和九幅离屏BGRA一致通过，覆盖四traits、宽/组合字符/Emoji、历史/resize、多提交。不是GUI隐藏恢复或资源压力全覆盖。原始patch、配对数据及像素结果见experiments/font-frame-cache.patch、font-mixed-results-v2.json、font-pixel-comparison-v2.json。第二个优化未实施。
